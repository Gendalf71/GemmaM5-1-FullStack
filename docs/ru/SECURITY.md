# Модель безопасности

Сервер проекта явно привязан к `127.0.0.1` и не включает CORS. Токен LM Studio передается только через `LM_API_TOKEN`.

Tool call является предложением модели, а не разрешением. Хост проверяет имя, JSON-схему, дополнительные поля, лимит времени и объем вывода. Строка от модели не передается в shell. Пример чтения Memory Pressure по умолчанию принимает только числовой loopback-адрес API и ровно один tool call, аргументы которого декодируются в пустой JSON-объект; удалённый endpoint требует отдельного явного флага.

MCP выключен по умолчанию. Разрешайте только необходимые `allowed_tools`; не открывайте домашний каталог, `~/.ssh`, профили браузеров, хранилища паролей и облачные учетные данные. Исполняемый MCP-запрос по умолчанию принимает только числовой loopback-адрес native API; удалённый endpoint требует отдельного явного разрешения, поскольку тело запроса и необязательный `LM_API_TOKEN` покидают компьютер.

SSH alias использует `IdentitiesOnly yes`. Проверка требует точного ответа для аккаунта `Gendalf71`, а не любой успешной GitHub-аутентификации.

## Непрерывная интеграция

GitHub Actions закреплены по неизменяемым commit SHA релизов, а не по изменяемым major-тегам. Checkout не сохраняет workflow-токен, job ограничен по времени, а Dependabot настроен предлагать проверяемые обновления actions.

## Инвентарь Git при публикации

Чистое рабочее дерево не доказывает, что прежний commit содержит только релизные файлы. `verify_git_inventory.sh` сравнивает полный Git-индекс с `SHA256SUMS` и обязателен перед автоматическим push. Автоматизация требует идентичность автора именно из локального `.git/config` и не принимает унаследованные глобальные значения, поэтому публикация не меняет и не использует молча настройки других репозиториев.

- Каждый путь из `SHA256SUMS` проверяется до верификации, staging или копирования в релиз; абсолютные пути и обход каталогов отклоняются.

## Границы публикации GitHub

Автоматизация не переписывает неожиданный существующий `origin`, отклоняет архивный репозиторий и несовпадение visibility вместо неявного изменения удалённого состояния. Любую исправляющую команду `git remote set-url` или смену visibility следует сначала проверить вручную.

## Граница endpoint, listener и Release

Текстовый, визуальный, tool- и smoke-test-клиенты по умолчанию принимают только числовые loopback HTTP(S)-адреса с путём `/v1`; credentials, query, fragment и удалённые hosts отклоняются до передачи данных или `LM_API_TOKEN`. Каждый listener на настроенном порту обязан быть loopback, а остановка требует `running=false` и отсутствия сокета. GitHub Release создаётся только из точного чистого commit `origin/main` с зелёным CI и совпадающими targets тегов.

## Обязательная аутентификация локального API

В LM Studio откройте **Developer > Server Settings**, включите **Require Authentication** и создайте API token с минимальными необходимыми правами. Перед запуском сервера безопасно введите его в текущем Terminal:

```bash
read -s LM_API_TOKEN
export LM_API_TOKEN
printf '\n'
```

`start_server.sh` требует `REQUIRE_API_AUTH=1`, проверяет отказ запроса без токена и успешный ответ с токеном. Shell-клиенты помещают заголовок в временный файл с правами владельца, поэтому token не появляется в аргументах `curl`.

## Неослабляемый целевой профиль

`config/local.conf` может задавать только осознанные локальные параметры либо усиливать пороги. Исполняемые сценарии отклоняют попытку отключить API-аутентификацию, уменьшить 24 ГБ памяти, 35 ГБ свободного места или macOS 26.0, изменить MacBook Air M5/Q4_0, открыть сетевой bind либо увеличить число параллельных предсказаний выше одного.

Запуск сервера отклоняет уже работающий LM Studio server. Если после запуска не проходит проверка listener или аутентификации, сценарий пытается остановить запущенный им сервер и явно сообщает о неудаче rollback.

## Целостность конфигурации

Перед чтением значений защищённым профилем полностью валидируются default и local configuration. Неизвестные и дублированные ключи, некорректные строки, CRLF, управляющие символы, symlink и файлы с записью для group/world отклоняются. Для `config/local.conf` рекомендуется режим 0600.
