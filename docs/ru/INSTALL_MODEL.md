# Установка Gemma 4 26B A4B на MacBook Air M5 с 24 ГБ памяти

## 1. Рабочая конфигурация

```text
Model: google/gemma-4-26b-a4b-qat
Format: GGUF
Quantization: Q4_0
Initial context: 8192
GPU offload: max
Parallel predictions: 1
Identifier: gemma4-local
Server: 127.0.0.1:1234
```

Gemma 4 26B A4B является MoE-моделью примерно с 25,2 млрд общих и 3,8 млрд активных параметров на токен. Активные параметры определяют вычислительную нагрузку, но не позволяют выбросить остальные веса из адресуемого пространства. Официальный каталог LM Studio указывает для выбранного пакета Q4_0 размер 15,60 GB, то есть примерно 14,53 GiB. Размер загрузки, место на диске и резидентное потребление единой памяти — разные величины; точный пакет выбранной ревизии может отличаться, а память дополнительно расходуется macOS, vision-трактом, KV-cache, runtime и приложениями.

Архитектурные 256K токенов не являются рабочей гарантией для 24 ГБ. Начальная точка — 8192; 32768 и выше считаются экспериментом.

## 2. Подготовка

Подключите питание, оставьте не менее 40 ГБ свободного места и закройте тяжелые приложения.

Откройте корень репозитория. После Git clone обычно используется `~/Projects/GemmaM5-1-FullStack`, а релизный ZIP распаковывается в версионный каталог `~/Projects/GemmaM5-1-FullStack-1.1.240`.

```bash
cd /путь/к/GemmaM5-1-FullStack
chmod +x scripts/*.sh scripts/*.py examples/*.sh examples/*.py
./scripts/verify_repo.sh
./scripts/preflight.sh
```

## 3. LM Studio

```bash
./scripts/install_lm_studio.sh
```

Откройте приложение один раз, затем новое окно Terminal:

Для этого профиля требуется LM Studio версии 0.4.11 или новее: именно в этой версии добавлена обновлённая chat template Gemma 4, необходимая для проверяемого reasoning/chat-профиля. Для комплекта 1.1.240 рекомендуется LM Studio 0.4.20 или новее. Preflight проверяет версию приложения и независимо проверяет фактические возможности CLI, а не доверяет одной строке версии.

```bash
lms --version
lms --help
lms load --help | grep -- --parallel
```

## 4. Загрузка модели

```bash
./scripts/download_model.sh
lms ls --json
lms ls --variants
python3 scripts/resolve_model_identity.py --format json
```

Идентификатор каталога и квантизация закреплены для этого профиля 24 ГБ и проверяются до скачивания. Resolver читает только машинный `lms ls --json` и требует ровно одну локальную модель, подтверждающую QAT, GGUF и `Q4_0`. Он возвращает два независимых значения: `ModelInfo.path`, который передаётся в `lms load --exact`, и `modelKey`, который проверяется после загрузки. Любое переопределение `MODEL_KEY`, неоднозначность, удалённый экземпляр LM Link и другая квантизация завершаются отказом.

## 5. Оценка памяти

```bash
./scripts/estimate_model.sh 8192
memory_pressure -Q
```

При недостаточном резерве, устойчивом желтом или красном Memory Pressure загрузку отложите.

## 6. Загрузка в память

Dry run:

```bash
./scripts/load_model.sh
```

Фактическая загрузка:

```bash
./scripts/load_model.sh --execute --context 8192
```

Сценарий передаёт `--parallel 1` и завершится отказом, если установленный CLI не поддерживает этот параметр. Это важно: на совместимом llama.cpp runtime LM Studio по умолчанию может разрешать больше одновременных генераций, что выходит за пределы профиля 24 ГБ.

Чтобы предварительно выгрузить все другие модели, запросите это явно. Сценарий потребует набрать `UNLOAD`:

```bash
./scripts/load_model.sh --execute --context 8192 --unload-others
```

Флаг `--yes` существует только для заранее проверенной автоматизации и не рекомендуется для первого запуска.

## 7. API и приемочные тесты

```bash
./scripts/start_server.sh
python3 tests/api_smoke_test.py --model gemma4-local
python3 examples/text_request.py
python3 examples/vision_request.py
python3 examples/safe_tool_call.py
```

Сервер явно привязывается к `127.0.0.1`; CORS и доступ из локальной сети не включаются. Запуск принимается только тогда, когда машинный статус LM Studio сообщает `running=true` на настроенном порту, а **каждый** найденный через `lsof` listener является числовым loopback-адресом. Все Python-клиенты API по умолчанию запрещают удалённый base URL; для передачи prompt, изображения, тестовых данных или `LM_API_TOKEN` за пределы компьютера требуется отдельный флаг `--allow-remote-base-url`.

Останавливайте сервер командой `./scripts/stop_server.sh`: сценарий требует `running=false` и полного исчезновения listener на настроенном порту.

## 8. Документы и RAG

PDF, DOCX и TXT проверяйте через интерфейс LM Studio. Текстовый документ может передаваться непосредственно или через retrieval. Скан без текстового слоя может потребовать внешнего OCR.

## 9. MCP

MCP выключен по умолчанию. Для API в этом профиле нужен LM Studio 0.4.11 или новее; рекомендуется 0.4.20 или новее и отдельное разрешение Server Settings. Начинайте с одного публичного read-only инструмента и поля `allowed_tools`. См. `docs/ru/MCP_SAFE_PATTERNS.md`.

## 10. Расширение контекста

```bash
./scripts/estimate_model.sh 12288
./scripts/estimate_model.sh 16384
```

Каждый режим испытывается отдельно. При продолжительном swap, ошибке vision или нестабильности вернитесь к 8192.


Заполните `benchmarks/m5-air-24gb.template.json` только измеренными значениями. Комплект не содержит выдуманного M5-бенчмарка.

## Зафиксируйте происхождение модели

После определения точного ключа зафиксируйте установленный вариант без публикации локальных путей:

```bash
make provenance
cat artifacts/model-provenance.json
```

Это отфильтрованный локальный отчёт, а не контрольная сумма внешних весов. См. [Происхождение модели](MODEL_PROVENANCE.md).

## Обязательная аутентификация локального API

В LM Studio откройте **Developer > Server Settings**, включите **Require Authentication** и создайте API token с минимальными необходимыми правами. Перед запуском сервера безопасно введите его в текущем Terminal:

```bash
read -s LM_API_TOKEN
export LM_API_TOKEN
printf '\n'
```

`start_server.sh` требует `REQUIRE_API_AUTH=1`, проверяет отказ запроса без токена и успешный ответ с токеном. Shell-клиенты помещают заголовок в временный файл с правами владельца, поэтому token не появляется в аргументах `curl`.

## Точный аппаратный профиль

`preflight.sh` не считает любой Apple Silicon с 24 ГБ эквивалентом целевой машине. Через машинный JSON `system_profiler` проверяются `MacBook Air` и token `M5`; дополнительно требуются arm64, не менее 24 ГиБ памяти и macOS 26.0 или новее. Другой Mac может оказаться совместимым, но не проходит этот профиль и должен оцениваться отдельной конфигурацией.

## Неослабляемый целевой профиль

`config/local.conf` может задавать только осознанные локальные параметры либо усиливать пороги. Исполняемые сценарии отклоняют попытку отключить API-аутентификацию, уменьшить 24 ГБ памяти, 35 ГБ свободного места или macOS 26.0, изменить MacBook Air M5/Q4_0, открыть сетевой bind либо увеличить число параллельных предсказаний выше одного.
