# Устранение неисправностей

## Команда `lms` не найдена

Откройте LM Studio хотя бы один раз и запустите новое окно Terminal. Проверьте:

```bash
lms --help
```

Только для старой установки можно попробовать bootstrap из каталога приложения:

```bash
~/.lmstudio/bin/lms bootstrap
```

## Нет параметра `lms load --parallel`

Обновите LM Studio до версии 0.4.11 или новее (рекомендуется 0.4.20 или новее), один раз откройте приложение и запустите новое окно Terminal. Проверьте обязательную возможность загрузчика:

```bash
lms load --help | grep -- --parallel
```

Не удаляйте защитную проверку и не полагайтесь на более высокий стандартный Max Concurrent Predictions: профиль 24 ГБ требует строго одного.

## Не найден ключ модели

```bash
lms ls --json
python3 scripts/resolve_model_identity.py --format json
```

Убедитесь, что загружена именно QAT-редакция, формат GGUF и квантование `Q4_0`. Ручное переопределение принимается только после той же проверки установленной модели:

```bash
python3 scripts/resolve_model_identity.py --format json
export MODEL_KEY="exact-model-key-from-that-output"
```

## Оценка памяти слишком велика

Закройте тяжелые приложения, осознанно выгрузите другие модели, уменьшите контекст и проверьте, что выбрано `Q4_0`. Частичный CPU offload не отменяет общей нагрузки на unified memory.

## Сервер уже запущен или слушает сеть

Остановите существующий сервер и запустите проектный сценарий повторно:

```bash
lms server stop
./scripts/start_server.sh
```

Сценарий требует поддержки `--bind` установленной версией CLI и после запуска проверяет listening socket. Адрес `0.0.0.0`, `*` или `[::]` считается ошибкой безопасности.

## SSH вошел не в тот аккаунт

```bash
ssh -G github-gendalf71 | grep -E '^(hostname|user|identityfile|identitiesonly) '
ssh -T git@github-gendalf71
```

Ответ обязан начинаться с `Hi Gendalf71!`. Проверьте `IdentityFile` и `IdentitiesOnly yes` в `~/.ssh/config`.

## `gh` вошел не в тот аккаунт

```bash
gh auth status
gh api user --jq .login
```

Перед автоматической публикацией последняя команда должна вывести строго `Gendalf71`.

## Smoke test не проходит vision

Убедитесь, что загружена vision-capable GGUF-редакция модели, а не text-only файл. Вернитесь к контексту 8192, перезапустите сервер и повторите тест при зеленом Memory Pressure.

## Проверка SHA256 не проходит

Не публикуйте измененный архив как исходный релиз. Распакуйте ZIP заново. После осознанной правки репозитория контрольные суммы должен пересоздавать только сопровождающий релиза.

## Чистый commit не проходит проверку инвентаря

Сравните `git ls-files` с `SHA256SUMS`. Чистого рабочего дерева недостаточно, если прежний commit уже отслеживает лишний путь. Удалите непреднамеренный файл из Git, добавляйте в манифест только осознанные релизные файлы и повторите `./scripts/verify_git_inventory.sh --require-clean`.

## Точная ссылка модели отклоняется

Не выбирайте другую квантизацию молча. Изучите ошибку `lms get`, при необходимости обновите LM Studio и повторите команду. Только для осознанного ручного выбора выполните `./scripts/download_model.sh --interactive-fallback`, выберите GGUF `Q4_0` и дождитесь проверки локального ключа модели.

## Точный аппаратный профиль

`preflight.sh` не считает любой Apple Silicon с 24 ГБ эквивалентом целевой машине. Через машинный JSON `system_profiler` проверяются `MacBook Air` и token `M5`; дополнительно требуются arm64, не менее 24 ГиБ памяти и macOS 26.0 или новее. Другой Mac может оказаться совместимым, но не проходит этот профиль и должен оцениваться отдельной конфигурацией.
