# Карта доказательств

Документ связывает публичные утверждения репозитория с исполняемыми средствами контроля. Он не заменяет приёмку на целевом Mac.

| Утверждение | Предотвращающий контроль | Проверяемое доказательство |
| --- | --- | --- |
| Точный профиль модели | Фиксированные catalog ID, GGUF и Q4_0 до download/load | Регрессионные проверки поиска и профиля |
| Рабочая точка MacBook Air M5 24 ГБ | Машинная проверка hardware, macOS, памяти и диска | Тест parser и аппаратный протокол |
| Одна генерация | `MAX_CONCURRENT_PREDICTIONS=1`, `--parallel 1` | Регрессионный тест parallel |
| Локальная сеть | Числовой loopback и проверка каждого listener | Тесты listener и server status |
| Аутентификация API | Запрос без token обязан завершиться отказом, с token — успехом | `verify_api_auth.sh` и регрессия |
| Ограниченные инструменты | Одно имя, один вызов, пустой объект аргументов, фиксированная команда | Tool-регрессия |
| Ограниченный MCP | Точный native API path и непустой `allowed_tools` | Функциональный MCP-тест |
| Точная GitHub-идентичность | Эффективный SSH config, точное приветствие и login `gh` | SSH/publication-регрессии |
| Точный публичный репозиторий | Owner/name, Public, archived state, description и main | JSON-validator GitHub |
| Детерминированный Release | Manifest-only staging, fixed ZIP metadata, две идентичные сборки и распаковка | Release-тесты и sidecar |
| Честные аппаратные данные | `not_measured` по умолчанию и строгая схема измерений | Benchmark-validator и запись владельца |

`make verify` выполняет статические доказательные проверки, `make benchmark-check` проверяет шаблон. Производительность, swap, температура и визуальный результат не считаются доказанными до измерения на указанном Mac.

## Новые доказательные controls в 1.1.240

Визуальные утверждения связаны с PNG-manifest и validator полей; производительность — с digest запроса и протоколом повторов; screenshots — с явным pending/captured/redacted state; backend support ограничен LM Studio.
