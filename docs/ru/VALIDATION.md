# Приемка и проверка

Статическая проверка:

```bash
./scripts/verify_repo.sh
```

Аппаратная приемка выполняется на целевом Mac: preflight, сбор среды, estimate 8192, Memory Pressure и swap до загрузки, одна модель, text/vision/tool tests, документ в LM Studio и 15 минут смешанной нагрузки.

Результаты записываются в `benchmarks/m5-air-24gb.template.json`. Поля заполняются только измеренными данными; `null` не заменяется предположением.

## Публикация результата

Канонический результат MacBook Air M5 заполняет только владелец репозитория после личных измерений. Сырые аппаратные отчёты храните в игнорируемом каталоге `artifacts/` до проверки и обезличивания; вычисленные или перенесённые с другого Mac значения публиковать нельзя.

## Сетевая и релизная приёмка

Сочетание loopback и отдельного LAN-listener является отказом. `scripts/status.sh` обязан успешно получить `/v1/models`. После остановки требуются `running=false` и отсутствие listener. Перед GitHub Release потребуйте совпадения локального `HEAD`, `origin/main`, зелёного CI и target тега через `scripts/create_github_release.sh`.

## Доказательные gates выпуска 1.1.90

`verify_repo.sh` теперь проверяет размеры схем и защищённые внешние поля. Runtime evidence владельца отдельно фиксируется командой `make hardware-report`, а общий acceptance запускается через `make fullstack`. Результаты автоматически в Git не добавляются.

## Граница повторной проверки распаковки

Unit-suite выполняется на исходном дереве до упаковки. После безопасной распаковки сценарий повторяет все статические gates с `--skip-unit-tests`: точный manifest и safe-ZIP validator доказывают тождество выпущенных файлов, поэтому длительные unit checks не дублируются в той же CI-задаче. Независимый финальный аудит версии 1.1.240 дополнительно повторил все 91 unit check и на чисто распакованном архиве.
